# Agent Writer

SillyTavern 扩展：**原生草稿 → 校验 → 重写** 三稿流水线。

当前版本 **0.1.0（骨架）** —— 只验证运行环境，①②③ 流水线尚未接入。

---

## 它要解决什么

DeepSeek V4.1 Flash 在 RP 上有个矛盾：

- **关思考** → 文笔很好，但缺剧情推理，容易出逻辑 bug
- **开思考** → 思维链一直在推理剧情，不做文字整理，写出来的不是人话

所以流程改成三稿：

| 阶段 | 做什么 | 用什么 |
|---|---|---|
| ① 草稿 | 正常生成，靠它出文笔 | 酒馆原生生成（你当前连接） |
| ② 校验 | 只找逻辑问题，输出结构化清单 | 独立配置，通常开思考 |
| ③ 正文 | 按清单改稿，保住原稿文风 | 独立配置，通常关思考 |

②③ 走**独立 API 配置**，所以「草稿用官网 API、校验用 coding plan」这种组合是支持的。

## 安装

### 方式一：从 GitHub 安装（推荐，平板尤其方便）

1. 把本仓库推到你自己的 GitHub（记得先把 `manifest.json` 里的 `homePage` 改成你的仓库地址）
2. 酒馆 → **扩展** → **安装扩展** → 粘贴仓库地址 → 安装
3. 刷新页面

之后要更新：改完代码推上去，在扩展管理里点「更新」即可。

> `manifest.json` 里 `auto_update: false` 是故意的 —— 只有你手动改 `version` 号并点更新才会拉取，避免写到一半被拉走。

### 方式二：手动放置

把整个文件夹放到：

```
SillyTavern/data/<你的用户名>/extensions/agent-writer/
```

或对所有用户生效：

```
SillyTavern/public/scripts/extensions/third-party/agent-writer/
```

> `manifest.json` 必须在**仓库根目录**，ST 的安装按钮靠它在根目录识别扩展。

## 使用

两个入口，**没有扩展设置抽屉**（一个开关占一整行不值当）：

1. **悬浮球** —— 同时是状态灯，点一下开/关面板。可拖动，会自动吸附到最近的屏幕边缘。
2. **扩展菜单项** —— 在扩展菜单里（和「织幕」「变量管理器」并列），右侧带行内状态，点开菜单不用开面板也能看到进度。

### 悬浮球状态

| 状态 | 外观 | 含义 |
|---|---|---|
| 待命 | 紫色，4 秒慢呼吸 | 就绪 |
| 草稿 | 青色，呼吸 + 环慢转 | ① 酒馆正在生成 |
| 校验 | 紫色，呼吸 + 环快转 | ② 校验中 |
| 改写 | 琥珀，呼吸 + 环快转 | ③ 改写中 |
| 完成 | 绿色，扩散环（4 秒后回落） | 完成 |
| 出错 | 红色，抖动两次 | 出错，球上显示问题条数 |
| 停用 | 灰色，静止半透明 | 自动模式已关 |

面板「参数」页有**状态演示**按钮，可以逐个预览，确认平板和手机上的表现。

> 系统开启「减弱动态效果」时，所有动画自动降级为只换颜色、不做位移。

## 自检

平板后端不方便开 devtools，所以内置了自检。

**面板 → 参数 → 运行自检**，会检查：

- `getContext()` 是否可用
- `ConnectionManagerRequestService` / `ChatCompletionService` / `generateRaw` 等关键 API
- 连接管理器是否被禁用、有哪些连接配置、每个配置是否可用
- `#extensionsMenu` / 悬浮球 / 面板是否挂载成功
- 当前视口尺寸、是否处于减弱动态效果模式

**测试当前连接配置** 会真的发一个 `max_tokens=8` 的请求（消耗极少额度），用来验证整条请求链路，并顺便确认该配置能否返回思维链。

结果可以点「复制结果」，或直接截图。

也可以在控制台直接调：

```js
aw.diagnose()          // 环境自检
aw.probe()             // 探测当前连接配置
aw.probe('<profileId>')// 探测指定配置
aw.show()              // 打开面板
```

## 出问题时

**关键路径上的失败会弹一个红框**（常驻、点一下关闭，完整信息在控制台）。如果启动阶段就崩了，你也会看到它，而不是一片空白。

如果连红框都没有，用调试入口：

```js
aw.show()        // 强制补挂并打开面板（最常用）
aw.diagnose()    // 环境自检，结果打到控制台
aw.getSettings() // 看当前设置
```

自检报告里的「界面挂载点」一节会告诉你：菜单容器探测到了没有、悬浮球在不在、面板在不在、`display` 是什么。

### 「测试当前连接配置」怎么读

它会**先试非流式，正文为空就自动改走流式**。

这个顺序是必要的：有些上游（实测 Cline 就是）**非流式的响应包裹格式酒馆解析不了**——HTTP 200、请求也成功，但 `content` 是空字符串。只看 HTTP 状态会得到一个**假的成功信号**。

```
【非流式】发送中…
  △ HTTP 通了，但没拿到正文
【流式】自动重试中…
  ✔ 正文: "OK"
=== 结论 ===
✔ 这条配置可用，走流式。
⚠ 非流式的包裹格式酒馆解析不了，这条配置必须开流式。
```

### 「请求体形状对照」

从最干净的 body 开始逐层加字段，用来二分定位是哪个字段导致上游拒绝：

```
① 极简 body（只有 messages + model）           → HTTP 400
② 加 chat_completion_source + custom_url      → HTTP 200 但正文为空
③ 再加 max_tokens + use_sysprompt             → 偶发 500
④ max_tokens 改成 1024                         → HTTP 200 但正文为空
⑤ 走 ConnectionManagerRequestService           → HTTP 200 但正文为空
```

**① 的 `上游报错: true` 是个陷阱**：`parsed.error === true` 是布尔值，说明这个 400 是酒馆自己编的（它从上游消息里提取文本失败），不是上游真返回的错误体。缺 `custom_url` 时酒馆不知道该往哪发。

### 已知会踩的坑（都已修）

- **`HTTP 200` 不等于成功**。必须检查 `content` 是否为空。上游包裹格式不被识别时，状态码照样是 200。
- **触摸点击被合成鼠标事件触发两次**：触摸结束后浏览器会补发一对 `mousedown`/`mouseup`，一次点击走两遍开关，点开又立刻关掉，看起来就是「点了没反应」。现在用 700ms 时间窗忽略合成事件，拖拽不受影响。
- **初始化时序**：`onEnable` 钩子在加载期就会跑，如果面板挂载和它共用「只跑一次」的闸门，`APP_READY` 的回调会被吞掉，面板永远不创建。现在 UI 和面板是两条独立路径。
- **模块缓存混版**：浏览器按 URL 缓存 ES 模块。如果部署时只改了一处版本号，会出现「旧模块 + 新代码」混着加载，典型症状是**上一版还有悬浮球，这一版什么都没有**。所以 `index.js` 里所有相对 import 都带 `?v=<版本>`。
- **菜单容器选择器**：酒馆没承诺过 `#extensionsMenu` 这个 id，所以做了多路探测（id → class → 按已知菜单项文字反推父容器），并用 MutationObserver 持续观察，菜单重建后能自动补挂。

## 文件结构

```
manifest.json      ST 扩展清单（必须在根目录）
index.js           入口：装配、生命周期钩子、设置读写
state.js           状态机 + 订阅（球和菜单项的唯一状态源）
diagnostics.js     自检与连通性探测
style.css          样式与动画
ui/
  fab.js           悬浮球：7 态动画、拖拽、触摸/鼠标双输入、resize 重夹位置
  menu.js          扩展菜单项：多路容器探测 + 行内状态
  panel.js         面板：内联模板 + 渲染、拖拽、页签、日志
```

> 面板模板内联在 `ui/panel.js` 的 `PANEL_HTML` 里，**没有 settings.html**。
> 走 `renderExtensionTemplateAsync` 需要酒馆按扩展文件夹名解析模板路径，
> 路径一旦对不上会静默失败，表现为「悬浮球能点但面板打不开」。内联之后这条失败路径不存在。
>
> **扩展目录里不允许出现 `.mjs`、`_dev/`、`node_modules/`** —— 开发工具一律放在仓库外面（见下方「开发说明」）。

### 三处为了「坏不掉」做的设计

1. **三个挂载点各自独立 try**。球、菜单项、面板任一环炸掉都不能连累其它两环，而且失败会弹红框。
2. **点球时就地补挂**。`safeToggle()` 会先检查面板在不在，不在就地补挂并给出可见反馈，而不是毫无反应。
3. **启动三重保险**。`APP_READY` 事件 + `onActivate` / `onEnable` 钩子 + 后台重试（共 50 次），谁先到都能把 UI 拉起来。

### 为什么图标都用 inline SVG

不用 emoji。同一个 emoji 在 Android / iOS / Windows 上字形、基线、颜色都不一样，而这个扩展要在平板、手机、电脑上通用。

### 为什么球的位置存在 localStorage

位置属于**纯客户端 UI 状态**。手机和电脑屏幕尺寸不同，把位置同步过去只会得到一个跑到屏幕外的球。

## 开发说明

只用 `SillyTavern.getContext()` 暴露的 API，**不深层 `import` ST 内部模块**。官方文档明确说深层导入随时会因内部结构变动而失效，而本项目没有本地酒馆环境可以快速定位问题。

调试入口挂在 `window.aw` 上。

### 开发工具在仓库外面

```
<工作区>/
├── agent-writer/          ← 上传到 GitHub 的只有这个目录
└── agent-writer-tools/    ← 本地开发用，永远不进扩展目录
    ├── smoke.mjs
    └── check-version.mjs
```

**扩展目录里绝不能出现 `.mjs` / `_dev/` / `node_modules/`。** 烟测脚本会往 `globalThis` 上装一个假的 `document`，万一被酒馆当模块加载，整页会直接崩。

### 改完代码的流程

```bash
cd ../agent-writer-tools
node check-version.mjs   # 版本号一致性 + 扩展目录无开发工具残留
node smoke.mjs           # 55 项断言
```

两条都绿了再推。`check-version.mjs` 会检查 `manifest.json` 的 `version`、`index.js` 的 `VERSION`、以及所有 import 的 `?v=` 是否一致——**这是防「混版加载」的**。

**改版本号要同时改三处**：`manifest.json` 的 `version`、`index.js` 的 `VERSION`、`index.js` 里全部 import 的 `?v=`。漏掉任何一处 `check-version.mjs` 都会报出来。

### 烟测覆盖什么

面板挂载与就地补挂、模板完整性（JS 引用的 id 是否都在模板里）、页签切换、状态机到悬浮球/菜单项的联动、徽标截断与自动清空、**触摸点击不被合成鼠标事件重复触发**、鼠标点击与拖拽仍正常、菜单容器多路回退、重复挂载不产生重复项。
